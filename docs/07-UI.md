# 07 — UI

## 1. Style preset — “evidence paper”

Not a SaaS dashboard. The object on screen is a document you can check, so the page borrows the
manners of a lab notebook and a bank statement: warm paper, ink, one red stamp for failure, one
green for pass, and hashes set in mono so they read as evidence rather than decoration.

| Token | Value | Use |
|---|---|---|
| `--paper` | `#f6f3ea` | page |
| `--card` | `#fffdf7` | panels |
| `--ink` | `#15171b` | body text |
| `--ink-soft` | `#5c5a52` | secondary text (never below 16px) |
| `--rule` | `#dcd5c4` | hairlines, 1px |
| `--oxide` | `#a8332a` | failure, cracked tiles, the stamp |
| `--ledger` | `#2e6b4f` | pass |
| `--brass` | `#8a6a2f` | signature / anchor accents |

Type: **Fraunces** (display, 44–64px, tight), **IBM Plex Sans** (body, 16px minimum, 17px in
panels), **IBM Plex Mono** (hashes, 13–14px, letter-spacing 0.02em). All three self-hosted as
woff2 with no CDN. Line length ≤ 68 characters for prose.

Density: one screen, no scrolling for the main loop at 1280×800. Every element that could be
mistaken for decoration must carry a number or a state.

## 2. Ruler — what we are measured against

Six references, screenshotted at 1440×900 from live sites (originals in `proof/rank/src/`).
For each: what we take, what we refuse.

| # | Reference | What we take | What we refuse |
|---|---|---|---|
| R1 | Etherscan — transaction detail | the “one object, many proofs” hierarchy: hash on top, decoded facts under it, everything linkable | its density and 13px labels; nothing on our page goes under 16px |
| R2 | GitHub Actions — run summary | a run as a strip of steps with per-step status, and a failing step that stays visible instead of scrolling away | its grey-on-grey; our failure is the only saturated colour on the page |
| R3 | crt.sh — certificate transparency search | the promise that a log is public and checkable by a stranger; the idea of a root you can quote | its raw-table presentation; we keep one object per screen |
| R4 | Sigstore Rekor — entry lookup | verification as a *first-class button*, with the verdict stated in words, not implied by colour | its developer-only vocabulary; our verdict sentence is plain English |
| R5 | ViewBlock — Arweave transaction | permanence made legible: a root, a time, a size, and a copy button | its crypto chrome; no wallet, no token, no price anywhere in our UI |
| R6 | HackerNoon article page | the reading rhythm judges already know: 68-character measure, 17–18px body, generous paragraph spacing | its ad slots and byline clutter |

## 3. One memorable point

**The tile strip.** A run is drawn as a row of small square tiles — one per step, each stamped
with the tool name and the first six characters of its hash. As the agent runs, tiles land left to
right and the row fills like a mosaic. When a bundle is tampered with, exactly one tile cracks:
it turns oxide red, the label under it names the field that moved, and the link to the next tile
turns into a dashed line. Nothing else on the page changes colour. A judge who remembers one
thing should remember *the cracked tile that says which field*.

## 4. Main screen spec

1280×800, three bands:

- **Band 1 (72px)** — wordmark `TESSERA` in mono with letter-spacing, and the line
  “Receipts for agent runs · verify offline”. Right side: a live self-audit chip
  `external requests 0` that counts `PerformanceResourceTiming` entries to other origins.
- **Band 2 (two columns, 560 + 520, gap 40)** —
  - Left: **Verify** — dashed drop zone (240px) reading “Drop a .tessera file, or use one of
    three samples”; below it three sample buttons (clean / tampered / forged) each with a
    one-line description and a byte size.
  - Right: **Verdict card** — 360px, paper-white, 1px rule. Big word PASS or FAIL in Fraunces
    56px, then a four-row check table (shape / chain / root / signature) with ms per row, then
    `steps`, `bytes`, `verified in`, and `root` in mono with a copy button.
- **Band 3** — the tile strip (full width, 96px), the selected tile's detail drawer below it
  (tool, arguments preview, result preview, `h`, `prev`, field commitments).

Secondary panels (same page, below the fold, reachable by anchor links in band 1):
**Record** (run the demo agent, seal, download), **Disclose** (pick a step, get a proof, verify it
alone), **Anchor** (Arweave packet, data root, what permanence buys and what it costs).

Empty, loading, failure and forged states are all designed; the failure state is the one we
screenshot for the submission.
